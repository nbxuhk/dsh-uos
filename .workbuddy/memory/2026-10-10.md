### 【重大教训】离线包内嵌依赖必须白名单，否则版本倒挂
- 现象：早前版本把 20 个 deb 全内嵌，安装后 `dsh-desktop` 停在
  `install ok unpacked`，返回码 1。
- 根因链：内嵌 `libgtk-3-0 3.24.41-1deepin8` 要求 `libgtk-3-common >= 1deepin8`，
  而系统是 `1deepin6` → dpkg 拒绝配置 `libgtk-3-0` → 连锁
  `libayatana-ido3-0.4-0` / `libayatana-indicator3-7` /
  `libayatana-appindicator3-1` / `dsh-desktop` 共 5 个包全部 unpacked。
- **正确策略**：DSH 主程序 9 个 Depends **均无版本约束**，在 UOS 桌面版全是系统
  基线。真正缺的只有 `Recommends: libappindicator3-1`（源中已废弃，ayatana 替代
  且默认未装）。故离线包**只内嵌 3 个**：
  `libayatana-appindicator3-1` + `libayatana-indicator3-7` + `libayatana-ido3-0.4-0`。
- install.sh 两段防护：① 先校验主程序依赖是否已由系统满足；② 装可选项时逐个
  跳过系统已装同名包，**绝不覆盖系统版本**。

### 【教训】两个"假验证"必须避免
1. **假断网**：`ip route del default` 因路由表存在重复默认条目而失效，脚本却
   record 了"已删除默认路由"。改为 `ip route del default via $GW dev ens33` +
   多次 `ip route del default`，并**复核路由表**。
2. **假对象**：验证脚本不记录被测包指纹，导致一轮验证跑的是**旧包**（日志里
   安装包体积 243507900 = 旧包，而新包是 263348366）。现已在结果文件中记录
   体积 + sha256。

## 环境坑（本项目专属，新会话必读）
- **SFTP 到 VM 整体不可用**：`put`/`get` 对多文件或大文件稳定抛
  `FileNotFoundError: [Errno 2]`（连空目录 mkdir 都报），`get` 建 0 字节文件。
  → 上传小文件用 **base64 管道**（`echo '<b64>' | base64 -d > 路径`），
  大文件传输**在 VM 内直接走 HTTP**。
- **`setsid -u` 不存在**（util-linux 的 setsid 无此选项）：切用户用
  `su <user> -c "..."`。
- **root 建的文件普通用户写不了**：日志路径别放 `/tmp`，放对应用户家目录。
- `/var/log/*.result` 由 root 创建，读取前需 `sudo chmod 644`；
  且 `sudo -S` 需要从 stdin 喂密码（`echo <pass> | sudo -S ...`），
  但脚本里再套一层 `sudo bash` 时密码已消耗，需注意。
- 读长文件用 **base64 回传**（`cat f | base64 -w0`）再本地解码，
  避免中文与控制字符在管道里被破坏。
